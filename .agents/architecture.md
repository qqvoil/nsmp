# NeverSMP Network Architecture

## Обзор Сети
Проект состоит из 11 серверов, которые динамически собираются из папки `core/templates/` скриптом `scripts/build_network.sh`.
- **Proxy**: Velocity (порт 25565)
- **Lobby**: Лобби сервер (порт 25566, rcon 25552)
- **Game Servers**:
  - SMP1, SMP2 (Обычное выживание)
  - anarchy1, anarchy2 (Анархия)
  - hardcore1, hardcore2 (Хардкор, `hardcore=true` в server.properties)
  - building1, building2 (Мирное выживание)
- **Limbo**: Резервный сервер авторизации (порт 25567)

## Глобальная База Данных (MySQL/MariaDB)
Все сервера объединены централизованной базой данных `neversmp` (настраивается в `scripts/setup_mysql.sh` и `configs/database_schema.sql`).
- **LuckPerms**: Синхронизируется глобально через MySQL (`apply_mysql_configs.py`). Права и префиксы, выданные на одном сервере, применяются везде моментально (`messaging-service: sql`).
- **PlayerTokens**: Глобальный баланс донат-валюты.
- **Auth (LimboAuth/Velocity)**: Единая авторизация.

## Интеграция с Сайтом (Backend)
- Движок сайта находится в `backend/` (Flask, `app.py`).
- Сайт выдает донат, подключаясь по RCON **только к серверам `lobby` и `smp1`**. 
- Это значит, что любые консольные команды с сайта (`pardon`, `p give`, снятие прав) приходят только на эти два сервера.
- Глобальные награды работают **только** за счет того, что команды с сайта изменяют MySQL (например, `lp user {player} permission unset...`), и эти изменения автоматически подхватываются остальными серверами, включая `hardcore`.

## Жизненный цикл серверов и Вайпы
- Ни в коем случае не редактируйте конфигурации напрямую в папке `server/`, так как при запуске `build_network.sh` они перезаписываются файлами из `core/templates/`. Все изменения должны вноситься в `core/templates/`.
- Плагины не хранятся в шаблонах. При сборке они копируются из `core/plugins_pool/` в соответствии с логикой фильтрации в `build_network.sh`.
- Вайпы производятся скриптом `scripts/wipe_server.sh`. Вайп удаляет только миры и локальные данные игроков (Essentials, WorldGuard), но **не** чистит глобальную БД. Поэтому для очистки банов или глобальных перков при вайпе требуются прямые SQL запросы к БД прямо из скрипта вайпа.

## Хардкор и Смерти
- На серверах хардкора отключено возрождение ванилой (`hardcore=true`).
- При смерти скрипты должны выдавать глобальное право `hardcore.dead` через LuckPerms (`execute console command "lp user %player% permission set hardcore.dead true"`). 
- Локальные баны (`tempban`, ванильный `ban`) использовать нельзя, так как хардкор-серверов несколько, и локальный бан позволит игроку зайти на второй сервер.
